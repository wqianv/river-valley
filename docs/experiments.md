# 十年实验与验收记录

2026-10-14，在 Linux 云环境、Python 3.12.14 上实际运行。全部实验种子 42、40 户、121 人、3,600 次日推进。没有玩家输入的基线由 NPC 独立运行。参数见 [模型说明](model.md)。

## 结果

| 实验 | 十年末粮食 | 累计收获 | 累计消费 | 缺食人日 | 上游末粮 | 下游末粮 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 正常气候 | 136,975 | 562,875 | 435,600 | 0 | 62,925 | 74,050 |
| 第 3–5 年连续干旱 | 0 | 126,891 | 138,187 | 297,413 | 0 | 0 |
| 正常气候，第 0 天截流 100% | 68,800 | 284,901 | 226,941 | 208,659 | 68,800 | 0 |
| 正常气候，第 0 天 h00 转给 h01 250 粮食 | 136,997 | 562,875 | 435,578 | 22 | 62,947 | 74,050 |

四组缺水人日均为 0。这不表示灌溉充足：饮水优先，缺食主要来自农业水不足或后续种粮耗尽。缺食没有死亡机制，指标反映所有固定居民未满足的口粮总量。

正常气候每年剩余库存增加；这是无腐败、无人口增长与固定劳动/土地的结果。干旱在第三年末把库存从 37,121 降至 3,296，第四年耗尽。第四年以后的低收获不能仅归因于天气，还存在“缺粮吃掉种粮 → 播种失败”的反馈；第六年恢复降雨也不会自动补出种子或粮食。本版没有保护种粮的策略，不能把这种结果当作现实社会预测。

截流把上游配水从 50% 改至 90%，其累计收获从 277,625 增至 283,500；下游累计收获由 285,250 降至 1,401，最终失去播种能力。渠道排水绕过下游农地的模型假设决定了此结果；没有战争或稳定度规则。

粮食转移在第 0 天仅改变所有权，总量不变。随后 h00 买粮，货币从基线的十年末 140 降至 0；h01 货币从 200 增至 387。转移实验 h00 累计消费少 22，缺食为 22，世界剩余库存因此比基线多 22。收获总量相同，而消费和交易发生真实变化。

## 复现

在仓库根目录执行；指定目录会替换同名输出文件。

```bash
python -m river_valley simulate --years 10 --seed 42 --scenario normal --output runs/experiment-normal
python -m river_valley simulate --years 10 --seed 42 --scenario drought --output runs/experiment-drought
python -m river_valley simulate --years 10 --seed 42 --inputs examples/divert.json --output runs/experiment-divert
python -m river_valley simulate --years 10 --seed 42 --inputs examples/transfer.json --output runs/experiment-transfer
python -m river_valley replay runs/experiment-normal/events.jsonl
python -m river_valley replay runs/experiment-drought/events.jsonl
```

## 验证与性能

`python -m unittest discover -v` 实际执行 **15 个测试，全部通过**。记录见 [测试输出](test-output.txt)，覆盖库存/货币守恒、错误行动的原子性、每日预算、玩家/NPC 同一规则、移动限制、公开供需、确定性、干旱窗口、降雨/截流的真实农业后果、转移后果、哈希篡改/中间事件删除、历史日期重放、存档续跑、CLI 和 HTTP 接口。长时测试推进正常与干旱各六年，并每日检查账本；十年实验也每步检查粮食、货币和水守恒。

正常情景另外完整运行十年，最终状态哈希与首轮一致；正常/干旱完整日志都通过独立重放，重放后的最终状态哈希分别与对应模拟摘要一致。

Chromium 实际访问网页，验证 121 个人物标记、40 个家庭行、按日/30 日推进、截流、重复行动拒绝反馈、外生降雨生效和 390px 移动宽度地图；未出现 JavaScript 错误。截图见 [map.png](map.png)。浏览器验收使用环境已有的 Playwright/Chromium；运行应用和 unittest 不需要这些组件。

独立运行正常情景十年，包含完整事件日志和年度快照：模拟计时 **11.9386 秒**，进程总墙钟 **11.9915 秒**，峰值 RSS **16,640 KiB**（Linux `resource.getrusage(RUSAGE_CHILDREN)`）。记录 82,803 个事件，日志 78,082,573 字节（约 74.47 MiB）。计时脚本只有一个模拟子进程。原始指标见 [benchmark.json](results/benchmark.json)。首轮同时运行多组实验及测试，正常耗时 18.7258 秒、干旱 19.9304 秒，不能作为独立性能比较。没有把零测试或仅开放端口算作验收。

## 已知局限与下一阶段

固定价格、固定调度与角色会产生顺序优势；无个人携带库存或跨村贸易，访邻村没有完整经济作用。缺食没有死亡或劳动力衰减；无粮食腐败、人口变化、土地退化、蓄水及天气预测。干旱后不可恢复暴露了种粮管理不足，不是必须发生的剧情。

下一阶段建议先加入独立种粮库存和保留策略、个人运输/跨村交易及可追溯交易报价；然后加入营养影响劳动、人口变化、粮食腐败和土壤/蓄水。每次只扩展一种状态约束，用成对种子实验和守恒测试检查它确实影响后续状态。再引入地方信息记忆、关系和协商，使截流能经具体行动产生反馈。暂不引入修仙、命运、LLM 或复杂部署。
