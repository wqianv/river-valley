# v0.1 模型说明

## 状态与尺度

一年 360 天，每季 90 天。上下游各 20 户，每户 3 人和 3 单位土地；玩家加入 h00，总人口 121。每人每天需要 1 食用粮和 1 饮水，初始总粮食为 12,100：11,980 单位食用粮和每户 3 单位、合计 120 单位种粮。每户货币 200，共 8,000。土壤肥力由种子初始化为 900–1100 整数，1000 为基准。

粮食、货币、水与作物均为整数；作物单位为粮食的千分之一。核心在 `core.py`，HTTP/UI 适配在 `web.py`，CLI 在 `__main__.py`。摘要和记录不作决策；无数据库或并行模拟。

## 水文

春夏秋冬日降雨基值为 100、80、110、90，加 -20..20 确定性日波动。每天随机生成器由 `seed:day` 初始化，无隐藏 RNG 游标。干旱仅在 `720 <= day < 1800` 将正常降雨除以 4 并取整；其余日相同。外生实验可替换为固定降雨，取消后恢复场景气候。

输入水 = 降雨 × 10。上游分配默认 50%，截流 0–100% 使其增至 90%，余量进下游。这里模拟渠道引水：上游分配的剩余渠道水在下游农地之后排出，不会回到下游灌溉入口；没有储水坝。

各村先满足所在地人口饮水，再灌溉。每单位已播种土地每日需 7 水；村内按土地需求比例分享不足。每步验证：

```text
输入水 = 饮水 + 灌溉 + 河口排出 + 渠道余水排出
累计输入水 = 上述四项的累计量之和
```

未满足饮水累计为缺水人日。水每天流走，暂无地下水、土壤蓄水或跨日存水。

## 农业与粮食

春秋前 30 天可播种，每次从独立种粮库存消耗 3 单位；每户每天最多一份劳动。玩家劳动后，家中 NPC 不能重复耕作。已播种且有劳动时：

```text
当日作物增长 = 8000 × (土地/3) × (土壤肥力/1000) × 灌溉满足比例
收获粮食 = 累计作物 // 1000
```

实现按每步整数除法取整。春秋第 90 天收获。收获优先补足本户 3 单位种粮储备，余量进入食用库存。储备不足时，系统会在当日消费前把食用粮转入种粮库存，直至储备达到 3 或食用粮耗尽。随后才结算口粮消费。千分之一单位的余数作为未食用残余丢弃，不进入粮食；作物增长代表外部生物生产过程。夏冬休耕。没有人工补粮路径，新总粮食只能由收获产生。

每天验证：

```text
当前食用粮 = 初始食用粮 + 分入食用账本的收获 - 消费 - 转入种粮
当前种粮 = 初始种粮 + 分入种粮账本的收获 + 转入种粮 - 播种耗粮
当前总粮食 = 初始总粮食 + 总收获 - 消费 - 播种耗粮
当前货币总量 = 初始货币
各户食用粮、种粮、货币、作物与累计消费/收获计数 >= 0
```

默认保留策略是每户至少留出一份 3 单位播种量；口粮消费不能扣减种粮库存。播种时扣种粮，收获后先补回储备。若食用粮和种粮都耗尽，仍无法播种，模型不提供外部种子。缺食只消费实际食用库存，短缺累积为缺食人日，不能借负库存。缺食没有死亡后果，全员仍会在下一日尝试行动。

## 有限信息与行动

身份、家庭和需求固定，所在地可变。观察 API 返回深拷贝：自家仓库和土地，以及所在地的公开供需。公开出售量为超过 180 粮食的余量，求助量为补足 30 粮食的缺口；异地库存和未来气候不可见。

- 农民在生长期提供劳动，播种必须先付得起种粮。
- 商人库存低于 90 且有钱时买入最多 30，选择本村最大的公开余粮报价；相同报价按固定家庭顺序择一。无报价时每 30 天可访邻村，下日回家。当前访问只改变位置，不携带货物或建立跨村贸易。
- 照料者自家粮食超过 240 时向本地公开求助家庭转移最多 6。

居民按固定 ID 顺序结算，便于复现，但存在先行动者优势。价格固定为 1；出售依据公开余粮报价，不另耗卖方行动。所有库存属于家庭，不为不同成员建立副本。

`act()` 先检查身份、每日额度、位置、目标、库存、公开报价和农时，再结算全部变化。玩家没有行动预算或库存特权。默认 NPC 不主动截流，但任何满足同样位置/家庭约束的上游居民都能调用该行动。

## 因果与重放

每条日志记录全部实际路径变化。转移记录双方库存，播种记录种粮支出，作物增长引用劳动与水文事件，水文引用最近的气候及闸门输入。沿累计作物的变化可追溯收获来源。

第一条 JSONL 事件含完整初始世界，此后记录路径旧值/新值并接续 SHA-256 链。重放验证 ID、时间、前序/内容哈希、旧值及最终账本；指定日期只验证读取的前缀。快照保存完整世界、下一事件 ID 和前序哈希，支持续跑。快照和哈希链不是数字签名。

相同 Python 3.12、种子、情景、输入顺序和天数得到相同状态与日志链。输出路径和性能耗时不属于模拟状态。状态版本 2 将食用粮与种粮分账；版本 1 快照和日志重放会在读入时迁移，并保持当时的总粮食不变。新快照、日志变化和续跑均携带两个账本及其守恒计数。
